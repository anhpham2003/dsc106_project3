NDVI Heatmap Viewer

NDVI (Normalized Difference Vegetation Index) measures how much living green vegetation is present in an area. Values near 1.0 indicate dense, healthy vegetation; values near 0 indicate bare soil, water, or snow. Colors go from light yellow (low) to dark green (high).

How to use this map:

  • Click a region box to zoom in and play an automated story of notable events.
  • Click the background to zoom back out.
  • Drag the slider to scrub through months from 2000 to 2025.
  • Scroll to zoom and drag to pan anywhere on the map.
  • Hover over the map to see the vegetation proxy value for any pixel.
  • Click "Highlight region" then drag on the map to see the average vegetation proxy for any area.

Greening and Browning of the Americas

Project 3

Jared Wang Hoang Pham Shaun Israni

This project explores long-term vegetation change across North and South America using MODIS-derived vegetation data. Our goal is to help viewers compare greening and browning patterns over time through an interactive map, timeline, region highlights, and guided annotations. The main question we investigate is: where in the Americas have vegetation patterns changed the most over time?

        Project Write‑Up

        Rationale for Design Decisions

        We wanted to provide the user with an experience in such that they could learn something. As such, we incorporated the following design choices:

        • (Guided) Zoom: We felt that although total freedom could be fun, it could be difficult to understand what was going on initially. As such, we decided to include a semi-guided user experience, where, by clicking on a region, the user would be brought to that specific region, and given a mini presentation of sorts, with data that we found interesting.
        • Panning + Manual Timeline: However, we did not want to limit the user experience to only what we had to show them. Rather, we wanted the users to be able to explore the data similarly to how we did. As such, we incorporated the ability to pan around the map, allowing the users to focus in on what they found interesting.
        • Hover/ Highlight: We did not want the users to be limited to visual interpretation, having to differentiate the different shades purely visually. Therefore, we incorporated the idea to display the NDVI value corresponding to that specific point, giving the user some more detailed information. This, however, did not generalize well when analyzing an entire area, so we decided to include a region highlighter, where users could define their own regions and see how the NDVI values changed as time went on.
        • Compare Mode: We also added a side-by-side comparison view so users could compare two different times without interrupting the main map's click-to-zoom story interaction.

        We did not arrive at these design choices immediately. Initially, we debated creating a more strictly guided, story‑like experience with dedicated pause and play controls. Ultimately, we chose the current approach because we believed it created a better balance between structured guidance and open‑ended exploration, allowing users to follow a narrative when they want to, while still having control over how they want to investigate the data.

        Development Process

        The project required approximately 16-20 of development time. Some of the most time consuming aspects were:

        • Exploratory Analysis: Deciding what events we would consider to be included within our guided timeline.
        • Implementing a zoom system that remained consistent across CSS scaling.
        • Ensuring that the event triggering logic would terminate when you clicked off the region/ would not duplicate or break the auto-scrolling when clicking directly from one region to another.
        • Preloading and caching ~300 monthly NDVI grids efficiently.

        Work was divided on a case-by-case basis, as our schedules did not always match up to work in together in real time. We coordinated our work primarily through a group chat; This made it easy to discuss ideas, ask questions, and hand off tasks when someone else was available to continue. We also gave updates through GitHub, using commit messages and shared documentation to keep track of progress. Through this, we were able to stay aligned even when working asynchronously.
